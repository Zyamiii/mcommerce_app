# HOA01: M-Commerce System and Architecture Setup

**Group:** Hamaza

## 1. System overview

**ShopEase** is a mobile commerce (m-commerce) system with two client applications that share one cloud backend:

| Component | Users | Platform | Entry point |
|---|---|---|---|
| Customer mobile app | Shoppers | Android / iOS (Flutter) | `lib/main.dart` |
| Admin dashboard | Store staff | Web browser (Flutter Web) | `lib/main_admin.dart` |
| Backend | — | Firebase (Authentication + Cloud Firestore) | `firestore.rules` |

Both apps are written in **Dart/Flutter** in a single VS Code project and reuse the same data models and services.

## 2. Architecture

```
┌────────────────────────┐        ┌────────────────────────┐
│  Customer Mobile App   │        │  Web Admin Dashboard   │
│  (Flutter Android/iOS) │        │  (Flutter Web)         │
│  Browse · Cart · Order │        │  Products · Orders ·   │
│  Track · Profile       │        │  Categories · Users    │
└───────────┬────────────┘        └───────────┬────────────┘
            │  shared lib/models + lib/services │
            └───────────────┬───────────────────┘
                            │ HTTPS / WebSocket (real-time listeners)
            ┌───────────────┴───────────────────┐
            │              FIREBASE              │
            │  Authentication (Email/Password)   │
            │  Cloud Firestore (NoSQL database)  │
            │  Security Rules (role-based access)│
            │  Hosting (admin dashboard)         │
            └────────────────────────────────────┘
```

It is a layered client–server design. Firebase is a Backend-as-a-Service, so no separate server code is needed:

1. **Presentation layer**: Flutter screens and widgets (`lib/screens/`, `lib/widgets/`, `lib/user/`, `lib/admin/`).
2. **State layer**: `Session` (`lib/providers/session_provider.dart`, a `ChangeNotifier` from the `provider` package) holds the signed-in user, their live profile and their live cart.
3. **Service layer**: `AuthService`, `ProductService`, `CartService`, `OrderService` and `UserService` (`lib/services/`). Every Firebase call goes through these.
4. **Data layer**: model classes (`lib/models/`) that convert to and from Firestore documents.
5. **Backend**: Firebase Authentication, Cloud Firestore and Security Rules.

## 4. Technology stack

| Concern | Choice | Reason |
|---|---|---|
| UI framework | Flutter 3.47 / Dart 3.13 | One codebase for mobile and web |
| IDE | Visual Studio Code with the Flutter and Dart extensions | Lightweight, hot reload |
| Authentication | `firebase_auth` | Managed email/password accounts |
| Database | `cloud_firestore` | Real-time NoSQL, offline cache |
| State management | `provider` | Simple and officially recommended |
| Formatting | `intl` | ₱ currency and date formatting |

## 5. Functional requirements

**Customer app:** register and log in, browse products by category, search, view product details, manage a cart, check out with delivery details and a payment method, track order status in real time, and edit their profile.

**Admin dashboard:** admin-only login; a dashboard of sales, orders, products and customers; create, edit, delete and hide products; manage categories; update order status (cancelling an order restocks its items); and view customers and grant admin access.

## 6. Environment setup (steps performed)

1. Installed the Flutter SDK and added it to PATH. Checked with `flutter --version`.
2. In VS Code, installed the **Flutter** and **Dart** extensions.
3. Created the project: `flutter create --org com.hoa --platforms android,ios,web mcommerce_app`.
4. Added the packages: `flutter pub add firebase_core firebase_auth cloud_firestore provider intl`.
5. Installed the tooling: `npm i -g firebase-tools` and `dart pub global activate flutterfire_cli`.
6. Checked the setup with `flutter analyze`, `flutter test` and `flutter build web`.
7. Tested on a physical Android phone (Android 13) connected by USB, instead of an emulator.
